## 3. 关键设计决策

### 3.1 不复用 CLI 的 `StatsService`

**决策**：Web 端自研 `WebStatsService`，重写与 `services/stats_service.py` 等价的查询。

**理由**：
- `services/stats_service.py:46-58` 用 `self._conn` 拿连接，假设 conn 在"调用方"线程里打开
- FastAPI 同步端点跑在 anyio threadpool，连接跨线程会爆
  `SQLite objects created in a thread can only be used in that same thread`
- 业务方法返回值结构（dict / list[tuple]）与 CLI 端对齐，模板不感知差异

**沉淀**：Web 端所有需要"线程安全 SQL"的场景都自研 Service；`services/` 层的 Service 是 CLI 专用、不能跨进程。

### 3.2 lifespan 阶段开独立连接

**决策**：`create_app()` 的 `lifespan` 阶段打开 `app.state.web_stats_conn`，关闭时关掉。

```python
app.state.web_stats_conn = sqlite3.connect(
    str(web_db), check_same_thread=False
)
app.state.web_stats_conn.row_factory = sqlite3.Row
```

**理由**：
- `check_same_thread=False` 是 FastAPI 同步端点的硬要求
- `app.state` 跨请求共享 + lifespan 生命周期管理，比每请求 `connect/close` 性能高 100x

**沉淀**：Web 端的 SQLite 连接**永远**走 `get_stats_conn`（即 `app.state.web_stats_conn`），**禁止**路由函数里 `sqlite3.connect(...)`。

### 3.3 `WebStatsService` 不在依赖注入时绑定 user_id

**决策**：`get_stats_service()` 返回 `WebStatsService(conn, user_id=0)`，路由内 `_bind_user(svc, user)`。

**理由**：
- `Depends(get_stats_service)` 拿不到 `user`（user 是 Optional，且路由层要判 None）
- 路由先判 `user is None → 302 /login`，否则 `_bind_user(svc, user)` 注入 user_id

**沉淀**：路由层显式判 user + 显式 bind。阶段 1 留下来的 hack，等 T-15 重构。

### 3.4 Pydantic schemas 收口

**决策**：Web 端所有 API 响应走 Pydantic 模型，不用裸 dict。

**理由**：
- 自动生成 OpenAPI 文档（`/docs` Swagger UI）
- 字段缺失 / 类型错时 422 而不是 500
- 模板拿到的是结构化对象，IDE 自动补全

**沉淀**：Web 端所有新 API 端点必须定义 Pydantic 响应模型；不要让模板"猜 dict 字段"。

### 3.5 进度条用内联 `<div>`，不引 ECharts

**决策**：Band 进度 / 等级分布用纯 CSS `<div class="bar">` 进度条，不引图表库。

**理由**：
- MVP 范围明确：5 个页面、不引复杂图表
- 进度条数据已经在 HTML 里，CSS 一行宽度：`width: 60%`
- 加 ECharts 多 200KB（vendored 或 CDN），收益小

**沉淀**：MVP 阶段能用 CSS 解决的视觉就别引库；后续要做趋势折线再考虑 ECharts（参考 T-09 PWA 时一起做）。
