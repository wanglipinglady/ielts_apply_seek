## 1. W8 阶段：MySQL 模式 + 未登录 阻断

### 1.1 用户原话（W7 文档第 4.3 节提出的债务）

> "保留 mysql 存储是为了后面 web 页面扩展时有数据可展示"
> "MySQL 模式 + 未登录 = 阻断"
> "SQLite 模式 + 未登录 = 允许"

### 1.2 决策表

| 决策点 | 选项 | W8 决定 | 理由 |
|---|---|---|---|
| 阻断点位置 | CLI 入口 / `get_user_id()` / Service 构造 | **CLI 入口** `_show_current_user` | 集中；Service 内部零侵入；既有 W7 行为改动最小 |
| 阻断方式 | SystemExit(1) / RuntimeError / click.Abort | **SystemExit(1)** + 红字 | CLI 工具友好；bash 脚本能 catch exit code |
| banner 文案 | 静默 / 软提示 / 硬退出 | **硬退出** | 红字"在线模式需要先登录。执行 `ib auth login <username>` 后重试。" |
| `auth` 子命令 | 阻断 / 不阻断 | **不阻断**（invoked == "auth" 跳过） | 用户没登录时也得能跑 `auth login` |
| W7 软提示路径 | 保留 / 移除 | **保留** | local 模式未登录仍走 W7 的"未登录 banner"软提示 |

### 1.3 实施

**`cli.py` `_show_current_user` 升级**：

## 2. W9 阶段：CLI `--mode` 选项

### 2.1 用户原话

> "新增 mode 选项……优先级最高"

### 2.2 决策表

| 决策点 | 选项 | W9 决定 | 理由 |
|---|---|---|---|
| CLI 选项语法 | `--mode` / `-m` / 子命令 | **`--mode`** | click 标准；与 `auth login --mode` 子命令的 `-m` 区分 |
| 优先级 | 全局 / 子命令 | **全局**（挂在 `cli()` 上） | mode 是跨子命令的运行时参数 |
| 优先级排序 | env / config / --mode | **`--mode` > `IELTS_BUDDY_MODE` > config.toml > 默认 local** | 跟 `get_mode()` 现有逻辑无缝衔接 |
| 落地方案 | 写 `os.environ` / 写 ctx.obj | **写 `os.environ`** | `get_mode()` 已经在读 env；零侵入 |
| 进程级 env 污染 | try/finally 还原 / 写入后不管 | **try/finally 还原** | pytest 同进程跑多测试时不能污染 |

### 2.3 实施

**`cli.py` 加 `--mode` 选项**：

```python
@click.group()
@click.option(
    "--mode",
    type=click.Choice(["local", "online"], case_sensitive=False),
    default=None,
    help="数据源模式（local=SQLite / online=MySQL）。"
    "优先级：--mode > $IELTS_BUDDY_MODE > config.toml > 默认 local。",
)
@click.pass_context
def cli(ctx, mode: str | None):
    if mode is not None:
        # 备份原值
        if "IELTS_BUDDY_MODE" not in os.environ:
            _MODE_ENV_BACKUP["delete"] = True
        else:
            _MODE_ENV_BACKUP["value"] = os.environ["IELTS_BUDDY_MODE"]
            _MODE_ENV_BACKUP["delete"] = False
        # 写新值
        os.environ["IELTS_BUDDY_MODE"] = mode
    try:
        if ctx.invoked_subcommand is not None:
            _show_daily_reminder()
            _show_current_user(ctx.invoked_subcommand)
    finally:
        # 还原
        if mode is not None:
            if _MODE_ENV_BACKUP["delete"]:
                os.environ.pop("IELTS_BUDDY_MODE", None)
            else:
                os.environ["IELTS_BUDDY_MODE"] = _MODE_ENV_BACKUP["value"]
```

### 2.4 W9 真实 bug：env 进程级污染

W9.verify 全量回归 1 个 fail：

```
FAILED test_w7_user_id_isolation.py::TestCLINoLoginFallback::test_unauthenticated_stats_show_does_not_block
   AttributeError: 'MySQLRepositoryContainer' object has no attribute '_conn'
```

**根因**：W9.1 把 `os.environ["IELTS_BUDDY_MODE"] = "online"` 写到了进程级 `os.environ`，**W9 测试套件**用 `monkeypatch.setenv("IELTS_BUDDY_MODE", "online")` 显式设过，**W9 测试结束**时 monkeypatch 会还原，**但** monkeypatch 还原是 pytest fixture 范围；**W9 测试套件跑完之后**，**下一个测试套件**（W7 isolation）开始时，W9 测试套件**内部子命令执行期间**的 env 残留**已经在 `os.environ` 里**——`get_mode()` 命中残留 env，走了 MySQL 容器（MySQL 不通，炸）。

**临时修复**：在 `cli()` 里加 `try/finally` 还原。但**临时修复有更深的问题**，见 W10。

## 3. W10 阶段：修复 W9 错位

### 3.1 用户发现的真 bug

W9 测试全过，但**用户真实 PowerShell 跑**发现：

```
PS> ib --mode online auth login wangliping
登录成功  user_id=1  username=wangliping  mode=local   ← 不对！应该是 online
提示：单机模式下 user_id 始终为 1，username 仅作展示。
```

**应该走 MySQL，结果走了 SQLite，user_id 固定 1**。

### 3.2 根因（用 click 调研脚本验证）

`docs/w10_click_order_check.py` 验证 click multi-command 调用顺序：

```
[CLI_ENTRY] cli() called, mode=online
[CLI_ENTRY] env before write = None
[CLI_ENTRY] cli() about to return, env='online'
[SUB] env='online'                       ← 子命令执行时 env 已经是 online
[RESULT_CALLBACK] env='online'           ← result_callback 在子命令之后
```

**调用顺序**：`cli()` → `subcommand()` → `@cli.result_callback()`

**W9 错位**：

```python
def cli(ctx, mode):
    if mode is not None:
        os.environ["IELTS_BUDDY_MODE"] = mode
    try:
        if ctx.invoked_subcommand is not None:
            _show_daily_reminder()      ← 这里 finally 已经触发了
            _show_current_user(...)     ← 此时还没 invoke subcommand
    finally:
        # finally 在 cli() 退出时触发，click 还没 invoke subcommand
        # 子命令执行时 env 已经被还原成空
        os.environ.pop("IELTS_BUDDY_MODE", None)
```

`finally` 在 `cli()` 函数退出时触发，**此时 click 还没 invoke 子命令**。子命令执行时 `os.environ` 已经是空（或者 monkeypatch 设的值），`get_mode()` 兜底成 local。

### 3.3 W9.2 测试为什么没抓到

W9.2 测试用 `monkeypatch.setenv("IELTS_BUDDY_MODE", "online")` **在测试代码里**显式设 env。CLI 入口 finally 还原时被还原成 monkeypatch 设的值（**不是空**），子命令执行时 env 仍然是 `"online"`——**测试通过**。但**真实 PowerShell 场景**下用户没设 env，CLI 入口写完被还原成空，子命令兜底成 local。

**根因**：测试用了 `monkeypatch.setenv` 这个**非真实**的环境，掩盖了"env 原本为空"的关键场景。

### 3.4 决策表

| 决策点 | 选项 | W10 决定 | 理由 |
|---|---|---|---|
| 还原位置 | `try/finally` / `@cli.result_callback()` / 装饰器 / 上下文管理器 | **`@cli.result_callback()`** | 唯一能在子命令执行**后**做事的 click 钩子 |
| 暂存机制 | 模块级 dict / ctx.obj / 全局变量 | **模块级 `_MODE_STATE`** | result_callback 没有 ctx 参数（click 8.x） |
| click 8.x result_callback 签名 | `def f(result, **kwargs)` | 同左 | 不能 `@pass_context` 拿 ctx（result_callback 调度走的是不同路径） |
| 现有 W9 测试 fixture 是否还要 delenv | 是 / 否 | **是** | `test_w7_user_id_isolation.py` 加 `monkeypatch.delenv("IELTS_BUDDY_MODE", raising=False)` |

### 3.5 实施

**`cli.py` 重构**：

```python
# 模块级状态：result_callback 没有 ctx 参数，只能用模块 dict
_MODE_STATE = {"set": False, "added": False, "old": ""}


@click.group()
@click.option("--mode", ...)
@click.pass_context
def cli(ctx, mode: str | None):
    if mode is not None:
        if "IELTS_BUDDY_MODE" not in os.environ:
            _MODE_STATE["set"] = True
            _MODE_STATE["added"] = True
        else:
            _MODE_STATE["set"] = True
            _MODE_STATE["added"] = False
            _MODE_STATE["old"] = os.environ["IELTS_BUDDY_MODE"]
        os.environ["IELTS_BUDDY_MODE"] = mode
    if ctx.invoked_subcommand is not None:
        _show_daily_reminder()
        _show_current_user(ctx.invoked_subcommand)


@cli.result_callback()
def _mode_env_restore(result, **kwargs):
    if not _MODE_STATE["set"]:
        return
    if _MODE_STATE["added"]:
        os.environ.pop("IELTS_BUDDY_MODE", None)
    else:
        os.environ["IELTS_BUDDY_MODE"] = _MODE_STATE["old"]
    _MODE_STATE["set"] = False
    _MODE_STATE["added"] = False
    _MODE_STATE["old"] = ""
```

### 3.6 W10 真实 bug 经历

| 现象 | 排查 | 修复 |
|---|---|---|
| `TypeError: _mode_env_restore() missing 1 required positional argument: 'ctx'` | `@cli.result_callback()` 签名是 `def f(result, **kwargs)`，没有 ctx | 删掉 `@pass_context`，改用模块级 `_MODE_STATE` |
| `AttributeError: 'NoneType' object has no attribute 'obj'` | `@pass_context` 装饰 result_callback 拿到了 `ctx=None`（click 8.x result_callback 不会传 ctx） | 彻底用模块级 dict |
| W10 跑完后 `test_w7_user_id_isolation.py::TestCLINoLoginFallback::test_unauthenticated_stats_show_does_not_block` 又 fail | W7 测试没显式 `delenv("IELTS_BUDDY_MODE")`，依赖测试执行顺序 | W7 测试 fixture 加 `monkeypatch.delenv("IELTS_BUDDY_MODE", raising=False)` |

### 3.7 W10 工程经验

**经验 M：click multi-command 调用顺序是 `cli() → subcommand() → result_callback()`**。`cli()` 退出时 click 还没 invoke 子命令，所以**任何"在 cli() 退出时做事"的机制（finally / atexit / 装饰器 close）都太早**。

**经验 N：click 8.x `@cli.result_callback()` 签名是 `def f(result, **kwargs)`**。`@pass_context` 拿到的是 `ctx=None`，因为 result_callback 走的是不同的调度路径。需要跨 cli/sub 传递状态时，**用模块级 dict**。

**经验 O：测试不能完全代替真实场景**。W9.2 测试用 `monkeypatch.setenv` 掩盖了"env 原本为空"的关键场景。**如果当时有 PowerShell 真跑验证，W9 当场就能发现**。教训：CLI 改动必须用真 PowerShell 跑一次端到端，不依赖 CliRunner 全通过。

## 4. W11 阶段：whoami 校验 session.mode

### 4.1 用户发现的真 bug

W10 修好后用户真实跑：

```
PS> ib --mode online auth login wangliping
登录成功  user_id=692  username=wangliping  mode=online

PS> ib --mode online vocab add "instrument" --meaning "工业" --band 5
-- 当前用户: wangliping (id=692, mode=online) --
已添加: instrument  工业

PS> ib vocab list-personal
-- 当前用户: wangliping (id=692, mode=online) --    ← 没传 --mode，但 banner 仍然是 online
（无输出）                                            ← 但 SQLite 里没数据
```

**两个 bug**：
1. banner 跟实际 mode 不一致
2. SQLite 走 user_id=692 查不到（数据在 MySQL）

### 4.2 根因

`AuthService.whoami()` 只读 `session.json`，不校验 `session.mode` 跟当前 `self._mode`：

```python
# W10 终点（whoami 仍信任 session）
def whoami(self):
    return self._read_session()    # 永远返回 session 内容，不管当前 mode
```

**调用链**：
- `_show_current_user(invoked)` → `svc.whoami()` → `whoami()` 读 session
- session 是 online 时**永远**返回 online user
- 业务命令按 whoami 返回的 user_id 查 DB，但 DB 容器用的是当前 mode 的容器（local 走 SQLite）
- **user_id 错位**：用 SQLite 容器查 user_id=692，SQLite 里没这条数据

### 4.3 决策表

| 决策点 | 选项 | W11 决定 | 理由 |
|---|---|---|---|
| whoami 校验 | 校验 / 不校验 | **校验** | 错位 bug 必须修 |
| 不匹配时返回 | None / 抛错 / 警告继续 | **None**（视为未登录） | 跟"session 不存在"行为一致，banner 自动走"未登录"分支 |
| 是否切 session 文件 | 分文件 / 共享 | **共享**（W11 暂不拆） | 用户已拍板"不做任何更改" |
| 写新词汇时 session 跟当前 mode 不一致 | 阻断 / 提示 | **banner 提示**（沿用未登录 banner） | 跟"未登录"行为一致，避免新 bug 引入 |

### 4.4 实施

**`auth_service.py whoami` 加校验**：

```python
def whoami(self) -> dict[str, Any] | None:
    """读取当前 session；不存在返回 None。

    W11：session.mode 必须跟当前 self._mode 一致才认账。
    否则视为未登录——避免 "用 online 模式登录后切 local 查 SQLite"
    出现 user_id 错位（W11 真实 bug）。
    """
    data = self._read_session()
    if data is None:
        return None
    if data.get("mode") != self._mode:
        return None
    return data
```

### 4.5 W11 真实 bug 经历

无重大 bug。**唯一一次**测试 fail 是 patch 路径写错（`ielts_buddy.services.vocab_service.create_repositories` 实际不存在，vocab_service 内部用了不同导入路径）。改成断言 banner 即可。

### 4.6 W11 工程经验

**经验 P：session 里存的 mode 字段必须跟当前 mode 校验**，否则"session 说我在线，业务跑 SQLite"会出现 user_id 错位。这种 bug 跑测试不容易抓（`AuthService` 默认 `mode=None` 走 config 兜底成 local，session 也是 local 时根本测不到），**只有真实 PowerShell 切换 mode 才能复现**。

**经验 Q：看到"user_id 查不到自己的数据"先怀疑"session 跟 mode 的关系"**，再怀疑"业务逻辑"。修对地方比修对代码重要。
