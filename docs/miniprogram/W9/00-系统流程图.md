## 二、关键数据流（5 个场景）

### 场景 1：一键登录

```
用户点「微信登录」
    ↓
[小程序] wx.login() → 拿到 code（5 分钟有效）
    ↓
[小程序] POST /api/wx/login { code, nickname? }
    ↓
[后端] wechat.py::api_wx_login
    ↓
[后端] _exchange_code_for_openid(code)
       ↓ 调微信 https://api.weixin.qq.com/sns/jscode2session
       ↓ 拿到 openid
    ↓
[后端] WebAuthService.login_by_wechat_openid(openid, nickname)
       1. 查 users 表 WHERE wechat_openid = ?
       2. 找到了 → 直接登录（更新 last_login_at）
       3. 没找到 → 自动建账号
       4. create_access_token 签发 JWT
    ↓
[后端] 返回 { access_token, refresh_token, user, is_new_user }
    ↓
[小程序] wx.setStorageSync('ib_access_token', token)
         wx.switchTab('/pages/study/index/index')  跳学习 Tab
```

### 场景 2：背单词（艾宾浩斯复习）

```
用户进「复习 Tab」→ 点「今日复习」
    ↓
[小程序] GET /api/wx/study/review/due
    ↓
[后端] ReviewService(user_id).get_due_words(limit=50)
       ↓ SQL: SELECT * FROM learning_records
       ↓      WHERE user_id = ? AND next_review <= today
       ↓      ORDER BY next_review ASC LIMIT 50
    ↓
返回 { due_words: [{word, meaning, phonetic, band, memory_level}], count, today }
    ↓
[小程序] 渲染 50 张翻面卡片
    ↓
用户点「认识」/「不认识」
    ↓
[小程序] POST /api/wx/study/review/submit { word, correct }
    ↓
[后端] ReviewService.record_learn(word, correct)
       答对：level +1，下次复习 +1/+2/+4/+7/+15/+30 天
       答错：level -2，下次复习立即
    ↓
返回 { word, memory_level, next_review_at }
    ↓
[小程序] 翻到下一张卡片
```

### 场景 3：口语录音评分

```
用户进「口语 Tab」→ 选 Part 2 → 抽题
    ↓
[小程序] POST /api/wx/speak/practice/start?part=2
    ↓
[后端] SpeakingPracticeService.start_practice(2)
       ↓ 从题库随机抽一道题
       ↓ 生成 session_id（30 分钟有效）
    ↓
返回 { session_id, part, part_label, question, vocab, sample_answer, tips }
    ↓
[小程序] 显示题目 + 「开始录音」按钮
    ↓
用户录音完成
    ↓
[小程序] POST /api/wx/speak/practice/submit (multipart/form-data)
       fields: session_id, part, topic_id, ..., actual_duration_sec, ...
       file: audio.webm (≤ 30MB)
    ↓
[后端] SpeakingPracticeService.submit(...)  ← 线程池（不阻塞事件循环）
       1. 保存音频到 ~/.ielts-buddy/audio/<session_id>.webm（7 天自动删）
       2. Whisper 转写音频 → 文本（30s 超时降级 fake）
       3. LLM 按 4 维评分（流利度/词汇/语法/发音，110s 超时降级 mock）
       4. 错词回收：MistakeService 写入错词本
       5. saving_records 入库
    ↓
返回 { record_id, transcript, scores, word_errors, grammar_errors, highlights, suggestions }
    ↓
[小程序] 显示评分（4 维雷达图 + 错词列表 + 改写建议）
```

### 场景 4：写作批改

```
用户在「我 Tab」→ 写作批改 → 粘贴作文 → 提交
    ↓
[小程序] POST /api/wx/grade/submit
       form: essay (50-10000 字符), task_type, topic
    ↓
[后端] _call_llm_grader(container, user_id, essay, topic, task_type)
       ← 直接 import Web 端 grade.py 的私有函数
       ↓
       1. GradingService.__new__() + 注入 _container/_repo/_user_id
       2. svc.grade_essay(essay, topic, task_type)
          ↓ 调 LLM（混元/DeepSeek）
          ↓ 110s 超时自动降级到本地 mock
          ↓ 返回 GradeResult
    ↓
[后端] _grade_result_to_mock_shape(grade_result)
       ← 把 GradeResult 转前端 mock-style dict
    ↓
[后端] save_result(user_id, grade_result)  ← 写入 grade_history
    ↓
返回 { success, result: { overall_score, band_scores, error_summary, suggestions, rewrite, ... }, source: "llm"|"mock" }
    ↓
[小程序] 显示 4 维评分 + 句级标注 + 段落结构 + 改写建议
```

### 场景 5：异常处理（事件触发型通知）

```
[任意服务] try { call_llm() } catch (e)
    ↓
[notifier.py] suppress(e, Severity.P2, signature="llm_timeout", max_retries=3)
    ↓
[notifier.py] _debouncer.increment_retry("llm_timeout")
    ↓
    if count < 3: return True   ← 继续重试
    else:           return False  ← 升级 P1
    ↓
[升级时] notify("llm_timeout 自愈失败", Severity.P1, signature="llm_timeout")
    ↓
[notifier.py] _send_wechat(message)  ← 调微信订阅消息
    ↓
[微信] 推送到你手机 → 微信震动叫醒你
    ↓
[notifier.py] _write_dead_letter(...)  ← 同步写 ~/.ielts-buddy/.dead_letter.log
```

## 四、关键技术决策

| 决策 | 原因 |
|------|------|
| 路径前缀 `/api/wx/` 与 Web `/api/` 隔离 | 评审清晰度 + 不污染 Web 端 API |
| 复用 Web 端 service 层（零改动）| 单一真相源 + 评审"血缘清晰" |
| `users` 表加 `wechat_openid` 字段（v3.9）| 让三端共用一张 users 表 |
| 异常通知用「事件触发」不用「定时轮询」| 避免半夜被刷屏，只在真出问题时叫你 |
| 不用 Docker | Python 项目部署简单，Docker 收益小 |
| 不用 Taro / uni-app | 微信原生足够 |
| TypeScript 不用 JavaScript | 编译时类型检查 |
| 5 分钟静默期聚合 | 同一 signature P2 只发 1 次 |

## 五、上线后真实运行链路

```
用户打开微信 → 搜「雅思搭子」→ 进入小程序
    ↓
[小程序] 检查 storage 有无 token
    ↓
    有 token → 调 /api/wx/config-check 验证
       ↓ 200 → 跳学习 Tab
       ↓ 401 → 清 token + 跳登录页
    ↓
    无 token → 跳登录页
    ↓
[小程序] 调 /api/wx/study/vocab/list
    ↓
[后端] 接收请求 → 鉴权 (Depends) → 路由 → service → repo
    ↓
[MySQL] SELECT ... → 返回数据
    ↓
[后端] 拼 JSON → 返回
    ↓
[小程序] 渲染 4 Tab + 首页内容
    ↓
用户操作（答题 / 录音 / 批改）
    ↓
重复上面的链路（数据写入 / 异常通知）
```

## 六、性能 + 可靠性设计

| 维度 | 设计 | 数字 |
|------|------|------|
| 并发 | uvicorn 异步 + 线程池 | 单进程可扛 100+ QPS |
| 长任务 | LLM/Whisper 走线程池 | 110s 超时降级 |
| 容错 | MySQL 失败 → fallback_sqlite | 0 服务中断 |
| 监控 | 16 个 notifier 测试 + 5 分钟静默期 | 半夜不被刷屏 |
| 重试 | 8 类自愈签名自动重试 | 不需要你介入 |
| 升级 | suppress 达 max_retries → 升级 P1 | 微信震动叫醒 |
