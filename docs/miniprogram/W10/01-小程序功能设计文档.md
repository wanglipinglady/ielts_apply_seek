# 微信小程序功能设计文档（v3.9 / 2026-09-21）

> 范围：`miniprogram/` 下所有页面 + 与之配套的 `/api/wx/*` 后端路由。
> 配套文档：本文档 + `02-三端协同设计.md` + `03-技术复盘.md` + `04-Spec沉淀.md` + `README.md`（入口导航）。

---

## 1. 设计目标

1. **移动端碎片化场景**：背单词 / 复习 / 口语练习都需要在手机上短时间完成。
2. **复用 Web 端能力**：所有数据/评分逻辑复用 Web 端 service 层，**零业务代码重复**。
3. **不重新设计后端**：Web 端已有 `/api/*`，小程序通过 `/api/wx/*` 物理隔离 + service 层复用方式接入。
4. **零学习成本**：4 个 tab（学 / 复习 / 口语 / 我），与 Web 端主导航一一对应。

| Tab | 入口 | 主要功能 | 配套后端 |
|---|---|---|---|

## 3. 详细功能设计

### 3.1 登录（`pages/auth/login`）

**用户场景**：第一次打开小程序，需要登录才能使用学习/复习/口语功能。

**实现逻辑**：

```js
// 简化流程
if (app.globalData.debug) {
  // IDE 真机调试模式：固定 mockCode，跳过 wx.login
  const mockCode = 'dev_test_user001';
  POST /api/wx/dev-mock-login { code: mockCode }
} else {
  // 正式环境：走 wx.login 拿 code
  wx.login({ success: loginRes => POST /api/wx/login { code: loginRes.code } })
}
```

**为什么用固定 mockCode**：之前用 `'dev_' + Date.now()` 每次登录都生成新用户，错题本/学习记录全丢。改固定后用户稳定可复现。

**登录后动作**：
1. `app.saveToken(access_token)` → 存 storage
2. `wx.setStorageSync('ib_refresh_token', ...)`
3. `wx.setStorageSync('ib_user', data.user)`
4. `wx.switchTab({ url: '/pages/study/index/index' })`

**关键设计**：
- `_afterLogin` 把 token / refresh / user 都存 storage，避免页面间反复登录
- `wx.switchTab` 而非 `wx.navigateTo`，让 tabBar 状态正确

### 3.2 学习 tab（`pages/study/index`）

**用户场景**：背词。3 个子模式（浏览 / 抽词 / 测验）。

**实现逻辑**：

#### 3.2.1 浏览模式
- 顶部 3 个统计卡片：连续天数 / 已学词数 / 待复习
- Band 选择（5-9）→ 调用 `/api/wx/study/vocab/list?band=7&count=20`
- 列表展示（单词 + 音标 + 释义 + 词性 + Band）

#### 3.2.2 抽词模式（**已内联到 study/index**，替代独立 random 页）
- 4 个数量按钮（5/10/15/20）→ 高亮显示当前选中
- 点「🎲 抽 N 个词」→ POST `/api/wx/study/vocab/random`
- 单卡片 + 翻转 + 认识/不认识按钮
- 认识 → POST `/api/wx/study/review/submit { word, correct: true }`
- 不认识 → 同样 submit + 错题本自动入（后端 `record_mistake`）
- 进度条 + 完成态 toast

**关键设计**：
- **不用 wx:for 循环数量按钮**：4 个独立 `onPick5/10/15/20` 方法 + 4 个独立的 `_activeClass` 字段（`countCls0/1/2/3`）。**WXML 三目表达式 `? :` 不支持**，所以用预计算字段。
- **数量选择响应式**：每次 setData 同时更新 4 个 class 字段，wxml 里直接 `{{countCls0}}` 引用。

#### 3.2.3 测验模式
- 入口按钮「开始测验 →」→ navigateTo quiz 页
- 单独 `pages/study/quiz` 处理（避免 study/index 过于臃肿）

### 3.3 复习 tab（`pages/review/index`）

**用户场景**：复习今天到期的词（艾宾浩斯算法）+ 查看错词本。

**实现逻辑**：

#### 3.3.1 今日复习（默认 tab）
- GET `/api/wx/study/review/due` → 拿到今日该复习的词列表
- 单卡片翻转：正面显示单词 + 音标，背面显示释义 + 记忆等级
- 「认识」/「不认识」按钮 → POST `/api/wx/study/review/submit`

#### 3.3.2 错词本 tab
- 跳转 `pages/review/mistakes`
- GET `/api/wx/study/mistakes` 拉错词列表
- 「已掌握」按钮 → POST `/api/wx/study/mistakes/{word}/mark-correct`

### 3.4 口语 tab（`pages/speak/index` → `pages/speak/practice`）

**用户场景**：按 Part 1/2/3 录音练习，AI 评分。

**实现逻辑**：

```js
// 简化流程
1. 进入 practice 页 → onLoad 自动调 /api/wx/speak/practice/start 抽题
2. 显示：topic + question + vocab + tips + sample_answer
3. 点大麦克风 → wx.getRecorderManager().start({ duration: 60000, sampleRate: 16000, format: 'mp3' })
4. 说话 → 点停止 → 录音文件路径存 this.data.audioPath
5. 点提交 → wx.uploadFile 上传到 /api/wx/speak/practice/submit（multipart）
6. 后端：whisper 转写 → LLM 4 维评分 → 错词回收 → 落库
7. 显示评分卡片：总分 + 4 维度 + 转写 + 纠错 + 建议
8. 底部 2 个按钮：重新录制（retryCurrent） / 下一题（nextQuestion）
```

**关键设计**：
- **采样率 16kHz / mp3 格式**：与 Whisper 直接兼容（whisper.cpp 接受 mp3）
- **max duration 60 秒**：雅思口语 Part 1 单题回答时长上限
- **重新录制 vs 下一题**：retryCurrent 复用同一 sessionId 后端走 update_audio（修复了 UNIQUE 冲突）；nextQuestion 调 start 拿新题
- **按钮全用 button 而非 view**：真机 tap 稳定（之前 `<view bindtap>` 在 IDE/真机偶发不响应）

### 3.5 我 tab（`pages/me/index`）

**用户场景**：查看个人信息 + 进入考试日历 + 退出登录。

**实现逻辑**：
- 顶部用户卡（头像 + 昵称 + 邮箱）
- 工具入口（**只保留「考试日历」**，其他功能移回 Web 端体验更好）
  - 决策记录：原计划有「AI 写作批改」「资料下载」3 个按钮，但实际使用中发现：
    - AI 写作批改：需要长文本输入 + 等待 LLM 评分（10-30 秒），小程序体验差 → 留 Web
    - 资料下载：资源大、下载管理麻烦 → 留 Web
  - 决策：只保留「考试日历」（查询类，适合小程序）
- 「退出登录」按钮 → 清 storage + reLaunch 回登录页

## 4. 关键设计原则

### 4.1 不重复业务代码

**原则**：所有 `/api/wx/*` 路由只做"端到端编排 + JSON 序列化"，业务逻辑完全复用 Web 端 service 层。

```python
# 范例：wx_speak.py
@router.post("/submit")
async def wx_speak_submit(...):
    # 路由层只做：参数解析 + 调 service + 序列化
    svc = SpeakingPracticeService(container=..., user_id=...)
    out: SubmitResult = await asyncio.to_thread(svc.submit, ...)
    return WxSubmitPracticeResponse(...)
```

### 4.2 物理隔离路径前缀

- Web 端：`/api/*` （auth / stats / study / speak / ...）
- 小程序：`/api/wx/*` （login / study / speak / grade）

**为什么分开**：
1. 安全边界：小程序用 JWT 但校验简化（防 domain 校验麻烦）
2. 数据契约不同：小程序返回更紧凑（fewer fields）
3. 路由清晰：grep `wx_*` 一眼看出小程序相关代码

### 4.3 真机调试专用路径

`POST /api/wx/dev-mock-login` 仅 dev 环境可访问（prod 403）。

**用途**：
- IDE 真机调试无需真小程序
- pytest 测试时跳过微信 API
- 传 `code = "test_<openid>"` 模拟任意用户

### 4.4 真机录音 API 选型

| 候选 | 选择 | 原因 |
|---|---|---|
| `wx.startRecord` (旧) | ❌ | 已废弃 |
| `wx.getRecorderManager` (新) | ✅ | 当前推荐，事件回调（onStart/onStop/onError）比 startRecord 灵活 |
| InnerAudioContext 播放 | ❌ | 不用于录音 |

**录音参数**：
- `duration: 60000`（60 秒上限，Part 1 单题足够）
- `sampleRate: 16000`（与 Whisper 兼容）
- `format: 'mp3'`（whisper.cpp 直接支持）

### 4.5 内联 vs 独立页面

**当前选择**：study/index 内联 random 学习流程，**不**走独立 `pages/study/random`。

**决策原因**：
- 之前有独立 random 页，但用户反馈"随机学习入口找不到"
- navigateTo 在某些机型上有兼容问题（页面卡顿、返回栈丢失）
- 内联后所有交互都在同一页面，状态管理更简单

**适用范围**：高频交互（抽词 → 认识/不认识）适合内联；独立流程（如 quiz 多题答卷）适合独立页。

## 5. 数据流概览

```
小程序发起请求
   ↓
[app.js: apiBaseUrl + /api/wx/...]
   ↓
FastAPI 路由（wx_*.py）
   ↓
Service 层（复用 Web 端）
   ↓
Repository（SQLite / MySQL）
   ↓
业务表 / 词库 / 用户隔离音频目录
```

### 5.1 关键数据

| 表 | 用途 | 主要字段 |
|---|---|---|
| `learning_records` | 艾宾浩斯复习记录 | user_id, word, memory_level, next_review, is_difficult |
| `vocab_cache` | 词库主表 | word, meaning, band, pos, phonetic |
| `mistakes` | 错词本 | user_id, word, source, wrong_count |
| `speaking_practice_records` | 口语练习记录 | user_id, session_id, audio_path, transcript, llm_scores, llm_suggestions |

### 5.2 用户隔离

- 所有业务表都带 `user_id` 字段
- 音频文件按 `~/.ielts-buddy/audio/<user_id>/<session_id>.<ext>` 隔离
- Service 层始终校验 `user_id`（不能查/改别人的数据）
