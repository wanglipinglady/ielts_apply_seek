## 二、踩过的坑（按时间线）

### 坑 1：域名 SSL 证书申请时填错主机名

**现象**：阿里云申请免费证书时，输入框疑惑填 `www.wanglipingresume.com` 还是 `wanglipingresume.com`。

**根因**：阿里云免费证书**自动包含 www 子域名**（签发时主域填裸域，自动 + www）。如果你填 `www.` 开头，反而只签 www。

**决策**：填 `wanglipingresume.com`（裸域），证书同时覆盖 `wanglipingresume.com` 和 `www.wanglipingresume.com`。小程序用的是子域名 `ielts.wanglipingresume.com`，需要在阿里云"补全域名"加钱（通配符证书）或为 `ielts.` 单独申请一张证书。

**教训**：子域名（`ielts.xxx.com`）必须**单独申请证书**，不能用主域免费证书覆盖；或者买通配符证书 `*.wanglipingresume.com`。

---

### 坑 2：ECS 防火墙没开 8001 却能访问

**现象**：阿里云 ECS 安全组里没开 8001 端口，但小程序能访问。

**根因**：阿里云 ECS 有**两层防火墙**——ECS 控制台安全组（外层）+ 系统内 `ufw`/`iptables`（内层）。Nginx 在公网 80/443 监听，请求**只到 Nginx**，Nginx 再代理到本地 8001。本地 8001 不需要对外暴露。

**教训**：Nginx 反代架构下，**后端端口永远不需要在公网开放**，安全组只放行 80/443。

---

### 坑 3：后端 .env 不生效（`未配置 WECHAT_APPID`）

**现象**：小程序登录报 `400: 未配置 WECHAT_APPID / WECHAT_SECRET`。

**根因**：systemd service 文件里用 `EnvironmentFile=/opt/ielts_apply_seek/.env` 加载环境变量，但 **Python dotenv 不识别 `#` 开头的行**——它把 `# 注释` 当成 value 的一部分，所以读取出来的 WECHAT_APPID 变成了 `未配置 # ...` 字符串。

**修复**：

1. 把 .env 里所有 `# 注释` 行**直接删除**（Python dotenv 协议里没有"注释行"概念）
2. service 文件改用 `Environment="KEY=VALUE"` 一行行写死（最稳）
3. 或者换 `EnvironmentFile=` + 在文件首行 `set -a` shell 模式加载（不优雅）

**教训**：**.env 文件不是 shell 脚本**，不能用 `#` 注释。systemd 的 `EnvironmentFile=` 默认行为是**逐行 `KEY=VALUE`**，对 value 里的特殊字符（`@`、空格、引号）有坑。

### 坑 4：502 Bad Gateway（uvicorn 进程在但端口没监听）

**现象**：Nginx 日志 `connect() failed (111: Connection refused)`，但 `ps` 看到 uvicorn 进程在跑。

**根因**：uvicorn 启动时配置 `--host 127.0.0.1 --port 8001`，但 `--workers 2` 时，主进程管理子进程 fork 时**子进程绑定失败**（端口被 systemd 的 `Type=simple` 误判为"主进程存活"）。systemd 只看主进程 PID，没看子进程是否真监听。

**修复**：

```ini
ExecStart=/opt/ielts_apply_seek/.venv/bin/uvicorn ielts_buddy.web.main:app --host 0.0.0.0 --port 8001 --workers 1
```

- 改 `--host 0.0.0.0`（绑所有网卡，systemd 不会拦截）
- 改 `--workers 1`（先单进程跑通，再考虑加 worker）

**教训**：

- systemd `Type=simple` 不验证子进程，必须用 `Type=forking` 或自己写健康检查脚本
- 端口监听验证用 `ss -tlnp | grep :8001`，**不要只看 `ps`**

---

### 坑 5：systemd Environment= 里 URL 含 `@` 被解析错

**现象**：`Can't connect to MySQL server on '666@127.0.0.1'`——host 部分被错位。

**根因**：DB URL `mysql+pymysql://remote_user:Pass@666@127.0.0.1:3306/...` 里的 `@` 让 systemd 把 `=` 后面的字符串**第二次拆键值对**，结果 `=` 后面被切成 `mysql+pymysql://remote_user:Pass` + `666@127.0.0.1:3306/...`，APP 拿到 host 变成 `666@127.0.0.1`。

**修复**（最简）：把 `@` URL 编码成 `%40`：

```ini
Environment="IELTS_BUDDY_WEB_DB_URL=mysql+pymysql://remote_user:Pass%40666@127.0.0.1:3306/ietls_learn_online?charset=utf8mb4"
```

PyMySQL / SQLAlchemy 收到 URL 后会**自己解码** `%40`，不需要改应用代码。

**教训**：

- systemd `Environment=` 对 URL / 密码里含 `@` / `:` / `%` 等字符**极其不友好**
- 长期方案：用 `EnvironmentFile=` + 文件权限 600，或写 systemd-creds 加密凭证

### 坑 6：MySQL CLI 连不上，但后端能连上

**现象**：`mysql -u remote_user -p'Pass%40666' ...` 报 `ERROR 1045 (28000): Access denied`，但后端 `/healthz` 显示 `mysql_reachable: true`。

**根因**：后端 .env 里 URL 写的是 `Pass%40666`（编码后），应用层 SQLAlchemy/PyMySQL 自动解码成 `Pass@666` 给 MySQL 协议用。MySQL CLI **不做 URL 解码**，把 `%40` 字面当成密码字符，所以密码不对。

**教训**：

- `%40` 编码是给 URL 解析用的，**MySQL CLI 不会自动解码**
- 想用 CLI 验证，要么用解码后的明文密码 `Pass@666`（但 shell 转义麻烦），要么用 `mysql_config_editor` 配 login-path
- **正确做法：以后密码设计就别含 `@`，避免所有麻烦**

### 坑 7：前后端 AppID 不一致 → 微信 40029

**现象**：`POST /api/wx/login` 返回 `errcode=40029 invalid code`。

**根因排查**：

1. 前后端必须用同一个 AppID + AppSecret，否则微信服务器拒绝
2. 小程序代码 `miniprogram/project.config.json` 里 `"appid": "wx5aac958e916e8199"`
3. 后端 service 里 `IELTS_BUDDY_WECHAT_APPID=wx286309bc641b1d79`
4. 两个 AppID 完全无关——一个是测试号，一个是正式备案号
5. 备案用的 `wx286309bc641b1d79` + secret 是真实的，但前端跑的是 `wx5aac958e916e8199` + 没 secret

**修复**：

1. 前端 `project.config.json` 改 AppID → `wx286309bc641b1d79`
2. 微信开发者工具 → 导入项目 → 用正式号扫码登录 → 清缓存 → 重新编译

**教训**：

- 项目里**两个 AppID** 是部署灾难——必须做到"前后端配置 source of truth"
- 部署前 sanity check：`grep -r "appid" miniprogram/` + `grep WECHAT_APPID /etc/systemd/system/ielts-web.service`
- 强烈建议用**单一变量中心化配置**（比如后端从同一份 yaml 文件读）

### 坑 8：`MySQLWebUserRepository` 缺 `get_by_openid` 方法 → 登录 500

**现象**：通过 AppID 校验后，后端查 DB 抛 `AttributeError: 'MySQLWebUserRepository' object has no attribute 'get_by_openid'`。

**根因**：登录逻辑 `service.login_by_wechat_openid()` 调用 repo 的 `get_by_openid`，但：

- `SQLiteWebUserRepository.get_by_openid` ✅ 有
- `MySQLWebUserRepository.get_by_openid` ❌ **缺失**

作者写仓储时只复制了基础5 个方法（email/id/last_login/password），把后来加的 `get_by_openid` / `bind_wechat_openid` 漏了。**SQLite 实现本地测试时一直用，本地从来没暴露过这个 bug——线上才暴露**。

**修复**：

1. 在 `MySQLWebUserRepository` 类里补 `get_by_openid` 和 `bind_wechat_openid`
2. **同时**清理 `__pycache__` + 硬杀 uvicorn 进程（见坑 9）

**教训**：

- 仓储类多实现时，**用 ABC 抽象基类强制方法签名一致**——少一个方法编译器/解释器立刻报
- 写完后跑一次 `dir(MySQLWebUserRepository)` 对比 SQLite 版本
- **集成测试要覆盖所有仓储实现**，不能只测 SQLite

---

### 坑 9：ORM 不知道新加的数据库列 → `AttributeError: wechat_openid`

**现象**：补完 `get_by_openid` 方法后又报 `AttributeError: wechat_openid`。

**根因**：MySQL 表已经 `ALTER TABLE users ADD COLUMN wechat_openid`，但 **SQLAlchemy 的 Table 对象**（`t_users_mysql`）在 Python 代码里**静态定义**——ORM 不知道有这个字段，所以 `t_users_mysql.c.wechat_openid` 抛 `AttributeError`。

**修复**：

在 `src/ielts_buddy/web/auth/repository.py` 第 502 行后加一列定义：

```python
Column("wechat_openid", String(64), nullable=True, unique=True),
```

**教训**：

- **生产项目应该用 Alembic** 做 schema migration，ORM 表定义和 DB schema 自动同步
- 当前这个项目 Table 是手写定义 + 数据库手动 ALTER，**两边失同步是常见 bug**
- 类似工具：SQLAlchemy `metadata.reflect(bind=engine)` 自动反射表结构（牺牲一些性能）

### 坑 10：uvicorn worker fork 缓存 + `.pyc` 缓存

**现象**：服务器文件确实改了，但 uvicorn 启动后**还是报旧错误**——`AttributeError: get_by_openid` 一字不差。

**根因**：

1. Python `__pycache__/*.pyc` 文件缓存了**旧版本**的编译产物，uvicorn 启动时优先加载 .pyc
2. uvicorn `--workers N` 模式下，**主进程 fork 出来的子进程** import 的是进程内 .pyc，磁盘改了它也不重新读

**修复（"硬刷新"）**：

```bash
# 1. 清磁盘缓存
find /opt/ielts_apply_seek -type d -name "__pycache__" -exec rm -rf {} + 2>/dev/null
find /opt/ielts_apply_seek -name "*.pyc" -delete

# 2. 硬杀进程（不是 restart）
pkill -9 -f "uvicorn ielts_buddy"
sleep 2

# 3. systemd 重新拉起
systemctl restart ielts-web
sleep 3

# 4. 验证（用 ss 看端口、用 tail 看启动日志）
ss -tlnp | grep ":8001"
tail -10 /var/log/ielts-buddy/web-error.log
```

**教训**：

- 改 Python 代码后**永远先清 `__pycache__` 再重启服务**
- 多 worker uvicorn 模式下，**新代码生效更慢**——fork 完才加载，新代码要等下次 worker 重启才生效
- 调试时临时加 `--reload` 参数可以热加载（但**生产禁用** `--reload`，内存泄漏）

### 坑 11：zsh 把 curl 多行命令拆开

**现象**：`curl -X POST url -H 'Content-Type: application/json' -d '{...}'` 在 zsh 下报错 `command not found: -H`、`command not found: -d`。

**根因**：zsh 把多行 shell 命令的换行当成命令分隔（mac 默认 zsh 比 bash 严格），每行当独立命令执行。

**修复**：一行写完（用 `;` 连接或直接连写），或加 `\` 续行符，或用 `bash -c "..."` 显式调用 bash。

```bash
# 错误（zsh 拆成 3 条命令）
curl -X POST https://example.com/api \
  -H 'Content-Type: application/json' \
  -d '{"code":"test"}'

# 正确（单行）
curl -X POST 'https://example.com/api' -H 'Content-Type: application/json' -d '{"code":"test"}'
```

**教训**：跨平台 shell 命令文档，**统一单行 + 单引号包参数**，避免 zsh/bash 行为差异。

### 坑 12：备案名称"智取屠鸭山"被驳回（游戏倾向）

**现象**：微信小程序备案审核驳回，理由"涉及游戏倾向"。

**根因分析**：

- "智取" + "屠鸭" + "山" 三个词组合，**审核员可能联想成"智取游戏道具/打怪闯关"**
- "屠鸭"虽是雅思考生黑话，但加上"智取"+"山"→ 容易解读为"游戏副本名"
- 头像设计有"山峰 + 学子 + AI 光环"——视觉上**也偏游戏风**

**修复决策**：

- 改名为"**屠鸭口语磨炼**"（6 字）
- 命名解析直接强调"工具属性"："屠鸭"（雅思黑话）+ "口语"（明确场景）+ "磨炼"（强调 AI 反馈循环下的刻意练习）
- logo 短名从"智取"改"屠鸭"
- 简介文案删除"全方位智取"等可能被误解为游戏的措辞
- 头像 prompt 改"麦克风/对话气泡 + 进步曲线"，避开山峰/攀顶/光晕等游戏感元素

**教训**：

- **备案名称审核是"宁严勿宽"**——中国文化里"屠鸭"+"智取"+"山"很容易联想成游戏副本
- 个人开发者主体 + AI 工具类目，**直白表达工具功能**最安全，不要玩文字游戏
- 提审前可以先用朋友的非正式号模拟审核视角

## 四、沉淀：以后部署必须检查的 6 件事（部署前 sanity check）

把这6 件事打包成 `scripts/deploy_preflight_check.sh`，每次部署前跑一遍：

```bash
#!/bin/bash
# 部署前 sanity check（v1 / 2026-09-29）
# 用法：bash scripts/deploy_preflight_check.sh

set -e
RED='\033[0;31m'
GREEN='\033[0;32m'
NC='\033[0m'

pass() { echo -e "${GREEN}[PASS]${NC} $1"; }
fail() { echo -e "${RED}[FAIL]${NC} $1"; exit 1; }

# 1. 前后端 AppID 一致
FRONT_APPID=$(grep '"appid"' miniprogram/project.config.json | sed 's/.*: *"\(.*\)",/\1/')
BACK_APPID=$(grep WECHAT_APPID /etc/systemd/system/ielts-web.service | sed 's/.*=//;s/"//g')
[ "$FRONT_APPID" = "$BACK_APPID" ] && pass "AppID 一致: $FRONT_APPID" || fail "AppID 不一致! 前端=$FRONT_APPID, 后端=$BACK_APPID"

# 2. 8001 端口真监听
ss -tlnp | grep -q ":8001" && pass "8001 端口在监听" || fail "8001 端口未监听"

# 3. MySQL 可达
curl -s http://127.0.0.1:8001/healthz | grep -q '"mysql_reachable":true' && pass "MySQL 可达" || fail "MySQL 不可达"

# 4. SSL 证书未过期（<=30 天）
CERT_DAYS=$(echo | openssl s_client -servername ielts.wanglipingresume.com -connect ielts.wanglipingresume.com:443 2>/dev/null | openssl x509 -noout -dates | grep notAfter | sed 's/notAfter=//')
echo "$CERT_DAYS" | xargs -I{} date -d "{}" +%s | xargs -I{} expr \( {} - $(date +%s) \) / 86400

# 5. .env 文件无 # 注释
grep -E '^[[:space:]]*#' /opt/ielts_apply_seek/.env && fail ".env 文件含 # 注释行（Python dotenv 会读取为 value）" || pass ".env 文件无 # 注释"

# 6. systemd Environment= 里无未编码 @
grep -E 'Environment=.*@.*' /etc/systemd/system/ielts-web.service | grep -v '%40' && fail "systemd Environment= 里含未编码 @" || pass "@ 全部 URL 编码"
```
