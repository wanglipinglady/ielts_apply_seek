# 雅思备考助手 ECS 部署手册（v3 / 分阶段验证版）

> **本版本特点**：每个阶段**独立可验证**，失败可回退，不需要一次性成功。
>
> **适用**：你的环境已有 Docker 容器 `mom-qa-mvp:1.0` 跑在 8000/8501 端口；我们部署雅思备考助手到 8001。

---

## 0. 部署前的关键认知

### 0.1 为什么"分阶段验证"

把整个部署当作 3 个**独立**的积木：

```
积木 A: 后端 uvicorn        → "雅思助手能独立跑吗？"
积木 B: Web 服务器 Nginx     → "Nginx 能服务静态页吗？"
积木 C: 反向代理            → "Nginx 能把请求转给 uvicorn 吗？"
```

每个积木坏了不影响其他。**先验证 A 再配 B，再连 A+B 验证 C**。

### 0.2 命令注解规范

每条命令我都会标**「是什么 / 为什么 / 失败会怎样」**三个标签：

- **是什么**：做什么
- **为什么**：原因
- **失败回滚**：错了怎么撤

## Phase 1：后端（uvicorn）独立部署

**目标**：在 ECS 上启动一个能响应 `/healthz` 的 uvicorn 进程，**不依赖 Nginx / 域名 / SSL**。

### 1.1 准备工作

```bash
# === 是什么：检查基础环境 ===
# 为什么：确认 Python 版本、是否在目标目录
python3 --version
# 期望: Python 3.10.x 或 3.11.x
pwd
# 期望: /opt/ielts_apply_seek（如果不在，cd 过去）
cd /opt/ielts_apply_seek
```

### 1.2 安装依赖

```bash
# === 是什么：用 pyproject.toml 安装所有 Python 包 ===
# 为什么：uvicorn / fastapi / pymysql / openai 等
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -e ".[web]"

# 验证（关键！）
python -c "from ielts_buddy.web.main import app; print('OK', app)"
# 期望: OK <fastapi.FastAPI object>
```

**失败回滚**：
- `ModuleNotFoundError: No module named 'ielts_buddy'` → 你不在 `/opt/ielts_apply_seek/`，cd 过去
- `pip install` 报错 → 看具体错误，常见是 `gcc` 缺失（`sudo apt install -y gcc python3-dev`）

### 1.3 写生产 .env

```bash
# === 是什么：把 LLM KEY / DB URL / 微信密钥写入文件 ===
# 为什么：uvicorn 启动时从这里读环境变量

# 先在 ECDHER 上生成 JWT secret（heredoc 外生成，变量才能展开）
JWT_SECRET=$(openssl rand -base64 48)

cat > /opt/ielts_apply_seek/.env <<EOF
IELTS_BUDDY_WEB_DB_MODE=online
IELTS_BUDDY_WEB_DB_URL=mysql+pymysql://remote_user:Pass@666@127.0.0.1:3306/ietls_learn_online?charset=utf8mb4
IELTS_BUDDY_LLM_API_KEY=sk-cp-crF61iHIxekGHshefJm0zWb6GFmL0x_tV47xBBYok369iI92IEWjdym7l6UXHXO-EmSyNqtJvd6v3qcjZdS-CoXH63u9Bt3Zl-EcA2mIF8ggnQdARmVp34c
IELTS_BUDDY_LLM_BASE_URL=https://api.minimaxi.com/v1
IELTS_BUDDY_LLM_MODEL=MiniMax-M2.7-highspeed
IELTS_BUDDY_ENV=prod
TZ=Asia/Shanghai
IELTS_BUDDY_JWT_SECRET=$JWT_SECRET
IELTS_BUDDY_WECHAT_APPID=wx286309bc641b1d79
IELTS_BUDDY_WECHAT_SECRET=把你的AppSecret填到这里
chmod 600 /opt/ielts_apply_seek/.env
EOF

# 验证
sudo cat /opt/ielts_apply_seek/.env
# 确认:
#   IELTS_BUDDY_WECHAT_APPID=wx286309bc641b1d79
#   IELTS_BUDDY_WECHAT_SECRET=不是"在这里"占位
#   IELTS_BUDDY_JWT_SECRET=长随机字符串
```

**为什么 heredoc 不加引号**：`<<EOF` 让 `$JWT_SECRET` 被 shell 展开；`<<'EOF'` 会保留为字面量字符串（错误）。

**失败回滚**：
- `mysql_pw` 输出「Unable to connect」 → 检查 DB_URL 的 host / password
- `JWT_SECRET` 是字面量 `$(...)` → 你用了 `<<'EOF'`，换成 `<<EOF`

### 1.4 前台启动 uvicorn（**关键步骤，先验证**）

```bash
# === 是什么：直接启动 uvicorn 看输出 ===
# 为什么：先验证能跑起来，再做 systemd 守护
source /opt/ielts_apply_seek/.venv/bin/activate

cd /opt/ielts_apply_seek
/opt/ielts_apply_seek/.venv/bin/uvicorn ielts_buddy.web.main:app \
  --host 127.0.0.1 --port 8001
```

**期望看到**：

```
INFO:     Started server process [12345]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://127.0.0.1:8001 (Press CTRL+C to quit)
```

**进程会一直跑着**（前台模式）。**另开一个 SSH session** 验证：

```bash
# 在另一个 SSH 终端
curl http://127.0.0.1:8001/healthz | python3 -m json.tool
```

**期望看到**：

```json
{
  "status": "ok",
  "app": "ielts-buddy-web",
  "version": "0.1.0",
  "prefer_mode": "online",
  "db_mode": "online",          ← 关键：连上了 MySQL
  "mysql_reachable": true,      ← 关键
  ...
}
```

**如果 `/healthz` 返回 502 / connection refused**：
- 前台 uvicorn 输出里一定有错误，看日志
- 常见：`pymysql.err.OperationalError: (2003, ...)` → DB_URL 错
- 常见：`openai.AuthenticationError` → LLM_KEY 失效

**前台验证通过后**，回到 uvicorn 那个终端，按 **Ctrl+C** 停止（**前台模式**会自动停）。

**失败回滚**：
- 启动失败 → 检查 `.env` 配置 → 修 → 重跑前台
- 完全删干净：`rm -rf .venv .env`（不影响其他东西）

### 1.5 配 systemd（守护进程）

```bash
# === 是什么：让 systemd 帮我们保活 uvicorn（挂了自动重启）===

# 用 tee 写 service 文件（避免 vim swap）
sudo tee /etc/systemd/system/ielts-web.service > /dev/null <<'EOF'
[Unit]
Description=IELTS Buddy Web (FastAPI on port 8001)
After=network.target

[Service]
Type=simple
User=admin
Group=admin
WorkingDirectory=/opt/ielts_apply_seek
EnvironmentFile=/opt/ielts_apply_seek/.env
ExecStart=/opt/ielts_apply_seek/.venv/bin/uvicorn ielts_buddy.web.main:app --host 127.0.0.1 --port 8001 --workers 2
Restart=always
RestartSec=5
StandardOutput=append:/var/log/ielts-buddy/web.log
StandardError=append:/var/log/ielts-buddy/web-error.log

[Install]
WantedBy=multi-user.target
EOF

# 创建日志目录
sudo mkdir -p /var/log/ielts-buddy

# 重新加载 systemd
sudo systemctl daemon-reload

# 启动 + 开机自启
sudo systemctl enable ielts-web
sudo systemctl start ielts-web

# 验证（关键！）
sudo systemctl status ielts-web
# 期望: Active: active (running)

curl http://127.0.0.1:8001/healthz
# 期望: status: ok, db_mode: online
```

**失败回滚**：
```bash
# 完全删除 service
sudo systemctl stop ielts-web
sudo systemctl disable ielts-web
sudo rm /etc/systemd/system/ielts-web.service
sudo systemctl daemon-reload
# 回到 1.4 重新前台启动调试
```

### Phase 1 完成标志

- ✅ `curl http://127.0.0.1:8001/healthz` 返回 `db_mode: online`
- ✅ `systemctl status ielts-web` 显示 active
- ✅ 上述是**完全独立**的——不依赖 Nginx、域名、SSL

**进入 Phase 2 之前，必须先完成上述三个 ✅**。

```bash

server {
    listen 80;
    server_name ielts.wanglipingresume.com www.ielts.wanglipingresume.com;
    return 301 https://ielts.wanglipingresume.com$request_uri;
}

server {
    listen 443 ssl http2;
    server_name ielts.wanglipingresume.com www.ielts.wanglipingresume.com;

    ssl_certificate     /etc/nginx/ssl/ielts.wanglipingresume.com/ielts.wanglipingresume.com.pem;

    error_log  /var/log/nginx/ielts-error.log;

        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
```

## 附：rsync include/exclude 语法陷阱（最容易踩的坑）

### 实际错误案例

```
$ uvicorn ielts_buddy.web.main:app
ModuleNotFoundError: No module named 'ielts_buddy'
```

即使：
- ✅ `.venv` 里装了包（`pip list | grep ielts` 能看到）
- ✅ `.env` 配置正确
- ✅ systemd service ExecStart 用绝对路径

**仍然报这个错**——说明 Python 找不到 `src/ielts_buddy/` 目录下的代码。

### 根因：rsync 的 `--include='src/***'` 不可靠

**危险写法**（rsync 版本相关，老版本可能不工作）：

```bash
rsync -avz \
  --include='/' \
  --include='pyproject.toml' \
  --include='src/***' \  # ← 这个语法在某些 rsync 版本下不生效
  --include='scripts/***' \
  --exclude='*' \
  ...
```

**结果**：只传了 `pyproject.toml` + `src/` 这个**空目录**，没传里面的 `.py` 文件。

### 诊断命令（在 ECS 上跑）

```bash
# 1. 看 src/ 下到底有什么
ls -la /opt/ielts_apply_seek/src/

# 期望看到:
# ielts_buddy/      ← 完整目录（含 __init__.py + web/ + services/）
# 

# 如果只看到 src/ 本身或空的 ielts_buddy/ → 没传成功

# 2. 看具体文件数
find /opt/ielts_apply_seek/src -name "*.py" | wc -l
# 期望: 100+（项目有约 200 个 .py）
# 如果: 0 或个位数 → 没传成功

# 3. 看 main.py 在不在
ls /opt/ielts_apply_seek/src/ielts_buddy/web/main.py
# 期望: 文件存在
# 如果: No such file or directory → 没传成功
```

### 推荐写法（保底）

**避免 `--include` 模式，用 `--exclude` 黑名单模式**（更可靠）：

```bash
rsync -avz \
  --exclude='.git' \
  --exclude='__pycache__' \
  --exclude='.venv' \
  --exclude='.runtime' \
  --exclude='*.pyc' \
  --exclude='.env' \
  --exclude='docs/' \
  -e "ssh -i ~/Downloads/你的密钥.pem" \
  /Users/wangliping/Public/selfProgram/ielts_apply_seek/ \
  admin@118.190.148.121:/opt/ielts_apply_seek/
```

**优势**：
- ✅ 简单不容易错
- ✅ 传**所有不在黑名单的文件**（包括隐藏文件，未来新增文件也不用改命令）
- ✅ rsync 各版本行为一致

### 修法（如果发现 src/ 是空的）

```bash
# 在 Mac 上重传
rsync -avz --exclude='.git' --exclude='__pycache__' --exclude='.venv' \
  --exclude='.runtime' --exclude='*.pyc' --exclude='.env' --exclude='docs/' \
  -e "ssh -i ~/Downloads/你的密钥.pem" \
```
