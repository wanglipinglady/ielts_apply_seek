# 三端协同设计文档（v3.9 / 2026-09-21）

> 范围：本地 SQLite 开发环境 / Web 端 / 微信小程序三端的登录流程、用户体系、数据共享机制。

---

## 1. 三端总览

| 端 | 入口 | 用户体系 | 数据库 | 主要场景 |
|---|---|---|---|---|
| **本地 SQLite**（dev） | CLI（`python -m ielts_buddy.commands.auth`） | web_user 表 | `~/.ielts-buddy/ielts_buddy.db` | 单元测试、离线开发 |
| **Web 端** | 浏览器（`http://127.0.0.1:8000`） | web_user 表（同 db） | 共享 SQLite | 长文本 / 大屏 / 全功能 |
| **微信小程序** | 微信（`wx5aac958e916e8199`） | web_user 表（同 db） | 共享 SQLite | 碎片时间 / 录音 / 移动 |

**核心**：**三端共享同一个 SQLite 数据库（`~/.ielts-buddy/ielts_buddy.db`）**，业务逻辑（service 层）完全复用，差异只在路由层 + 序列化层。

## 2. 用户表（web_user）

所有三端用户都存在同一张表 `web_user`：

```sql
-- 实际 schema 简化
CREATE TABLE web_user (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    email TEXT NOT NULL UNIQUE,  -- 自动生成 "wx+<openid>@wechat.ielts-buddy.local"
    password_hash TEXT,
    openid TEXT,                  -- 微信登录专用
    nickname TEXT,
    created_at TEXT,
    last_login_at TEXT
);
```

**关键字段**：
- `email` 是唯一约束（自动生成，登录时当 username 用）
- `openid` 是微信登录的 bridge，Web / CLI 用户为 NULL
- `password_hash` 仅 Web / CLI 用户有

**Web 端邮箱命名**：
- `username@example.com` （用户手动注册）

**小程序端邮箱命名**：
- `wx+<openid>@wechat.ielts-buddy.local` （自动生成，避免冲突）

## 3. 三端登录流程

### 3.1 本地 SQLite / Web 端登录

```
用户输入用户名/密码
   ↓
POST /api/auth/login { username, password }
   ↓
WebAuthService.login(username, password)
   ↓
1. 查 web_user (email = username)
2. bcrypt 验证 password_hash
3. 签发 JWT (access_token + refresh_token)
   ↓
返回 { access_token, refresh_token, user }
```

**对应代码**：
- 前端：`src/ielts_buddy/web/templates/pages/login.html`
- 后端路由：`src/ielts_buddy/web/routers/auth.py:438` (HTML GET /login)
- 后端 service：`src/ielts_buddy/web/auth/service.py`

### 3.2 小程序登录（dev 模式）

```
小程序启动（debug=true）
   ↓
用户点「微信一键登录」
   ↓
IDE 模式跳过 wx.login，直接 POST /api/wx/dev-mock-login { code: 'dev_test_user001' }
   ↓
WebAuthService.login_by_wechat_openid('dev_test_user001')
   ↓
1. 查 web_user (openid = 'dev_test_user001')
2. 不存在则自动注册（email = 'wx+dev_test_user@wechat.ielts-buddy.local'）
3. 签发 JWT
   ↓
返回 { access_token, refresh_token, user, is_new_user }
   ↓
小程序存 token + user 到 storage
   ↓
wx.switchTab 到 /pages/study/index/index
```

**对应代码**：
- 前端：`miniprogram/pages/auth/login/index.js` (line 30-35 debug 模式分支)
- 后端路由：`src/ielts_buddy/web/routers/wechat.py:174` (POST /api/wx/dev-mock-login)

### 3.3 小程序登录（正式环境）

```
小程序启动（debug=false）
   ↓
用户点「微信一键登录」
   ↓
调 wx.login() 拿 code
   ↓
POST /api/wx/login { code, nickname? }
   ↓
1. 后端拿 code 调微信 API code2Session 拿 openid + session_key
2. WebAuthService.login_by_wechat_openid(openid, nickname)
3. 同 dev 模式后续流程
   ↓
返回 token + user
```

**对应代码**：
- 后端路由：`src/ielts_buddy/web/routers/wechat.py:109` (POST /api/wx/login)
- 微信 API 调用：`src/ielts_buddy/web/routers/wechat.py:_exchange_code_for_openid`

### 3.4 流程对照

| 步骤 | 本地 SQLite / Web | 小程序 dev | 小程序正式 |
|---|---|---|---|
| 用户输入 | username + password | 固定 mockCode | 微信 wx.login() |
| 拿到 openid/code | username → email 查 | 'dev_test_user001' | code → wx API → openid |
| 查/建 web_user | ✅ | ✅ | ✅ |
| 签发 JWT | ✅ | ✅ | ✅ |
| 存 token | HTTP-only cookie | wx storage | wx storage |
| 后续请求头 | Cookie: session=... | Authorization: Bearer ... | Authorization: Bearer ... |

## 4. 用户隔离

### 4.1 数据隔离

**所有业务表都带 `user_id` 字段**：

```sql
-- 业务表示例
CREATE TABLE learning_records (
    id INTEGER PRIMARY KEY,
    user_id INTEGER NOT NULL,  -- 关键
    word TEXT,
    ...
);
```

**Service 层校验**：

```python
class SpeakingPracticeService:
    def __init__(self, container, user_id: int):
        self._user_id = int(user_id)  # 强制 int，避免 SQL 注入

    def submit(self, ...):
        # 所有 SQL 都带 WHERE user_id = ?
        record_id = sp_repo.create_practice_record(
            user_id=self._user_id,  # ← 必传
            ...
        )
```

### 4.2 文件隔离

音频文件按 user_id 分目录：

```
~/.ielts-buddy/
  audio/
    1/                            # user_id=1
      abc123-session-id.mp3
    48/                           # user_id=48（dev_test_user001）
      f1290edb-87af-4770-b670-5405d78ca493.mp3
```

**清理策略**：用户删除账号 → 物理删除 `audio/<user_id>/` 整个目录。

### 4.3 Token 校验

**Web 端**：session cookie，FastAPI Depends 自动校验
**小程序**：每次请求带 `Authorization: Bearer <access_token>` header

```python
# 后端：routers/wx_speak.py
async def wx_speak_submit(
    request: Request,
    user: Annotated[WebUser, Depends(get_current_user)],  # ← 自动校验
    ...
):
    # user.id 是可信的（已通过 JWT 验证）
    svc = SpeakingPracticeService(container=..., user_id=int(user.id))
```

## 5. 数据同步机制（v3 后引入）

### 5.1 双模式设计

```python
# config.py
def _resolve_db_mode() -> str:
    """默认 online，失败自动降级到 sqlite"""
    env = os.environ.get("IELTS_BUDDY_WEB_DB_MODE", "online")
    if env in ("online", "mysql"): return "online"
    if env in ("sqlite", "memory"): return "sqlite"

WEB_DB_MODE = _resolve_db_mode()  # 模块加载时决定
```

**两种模式**：

| 模式 | 后端存储 | 适用 |
|---|---|---|
| **online** | 远程 MySQL（118.190.148.121） + SQLite 镜像 | 生产 / 多用户 |
| **sqlite** | 仅 SQLite | 本地开发 / 测试 |

### 5.2 fallback_container

```python
# repositories/fallback_repo.py
def create_fallback_container(sqlite_db_path, mysql_url, prefer_mode):
    # 1. 尝试连 MySQL
    if prefer_mode == 'online':
        try:
            online = MySQLRepositoryContainer(mysql_url)
            online.health_check()
        except Exception:
            online = None

    # 2. 始终有 SQLite
    offline = SQLiteRepositoryContainer(sqlite_db_path)

    # 3. 包装为 FallbackContainer
    return FallbackContainer(online=online, offline=offline, prefer_mode=prefer_mode)
```

**行为**：
- online 模式：写 MySQL + 异步同步到 SQLite（用于本地缓存）
- sqlite 模式：所有读写走 SQLite
- online 失败：自动降级到 sqlite

### 5.3 sync_worker 后台同步

```python
# services/sync.py
start_sync_worker(
    container=app.state.container,
    interval_seconds=30,  # 每 30 秒一次
)
```

**同步内容**：
- 把本地 SQLite 的改动 push 到远程 MySQL（personal_vocab 等）
- 把远程 MySQL 的最新数据 pull 到本地 SQLite
- 写 sync_meta 记录最后成功时间

## 8. 三端协同完整流程示例

### 场景：小明第一次登录小程序

```
1. 小程序启动
   ├─ wx.storage 检查 ib_access_token
   │   └─ 不存在 → 显示登录页
   └─ onLoad 读 app.globalData.debug

2. 登录页
   ├─ debug=true → 显示"调试登录面板"
   │   └─ 默认 mockCode = 'dev_test_user001'
   └─ 用户点「微信一键登录」

3. POST /api/wx/dev-mock-login
   {
     code: 'dev_test_user001',
     nickname: '小明'
   }
   ↓
4. 后端：wechat.py:174 api_wx_dev_mock_login
   ├─ web_config.WECHAT_DEV_ALLOW_MOCK = True（dev 环境）
   ├─ mock_openid = 'dev_test_user001'
   ├─ WebAuthService.login_by_wechat_openid(mock_openid, nickname)
   │   ├─ 查 web_user (openid = 'dev_test_user001')
   │   ├─ 找到 user (id=48) → 直接用
   │   └─ 签发 JWT (access_token + refresh_token)
   └─ 返回 { access_token, ..., user: {id: 48, email: 'wx+dev_test_user@wechat.ielts-buddy.local'}, is_new_user: false }

5. 小程序存 token + user
   ├─ app.saveToken(access_token)
   ├─ wx.setStorageSync('ib_refresh_token', ...)
   ├─ wx.setStorageSync('ib_user', user)
   └─ wx.switchTab('/pages/study/index/index')

6. 学习页加载
   ├─ onShow 读 user from storage
   ├─ 显示 连续天数/已学词数/待复习
   └─ 默认在「浏览」tab → loadBrowse()

7. 后续每次请求都带 Authorization: Bearer <token>
   ├─ GET /api/wx/study/vocab/list?band=7
   │   ├─ get_current_user() 校验 token → user.id = 48
   │   └─ 返回 user_id=48 的词库
   └─ 其他 API 同理
```

### 场景：小明同时在 Web 端操作

```
Web 端登录 → 同 web_user (id=48)
   ├─ session cookie 存 web_session_<id>
   └─ 后续请求 cookie 自动带

Web 端学习 + 小程序学习 = 同一 user_id
   ├─ Web 端加一个词 → 写到 learning_records (user_id=48)
   ├─ 小程序「今日复习」 → 看到 Web 端加的词
   └─ 双向实时同步（基于 SQLite 共享）
```

## 10. 安全考虑

### 10.1 JWT 安全

- `JWT_SECRET` 必须设置（生产用强随机，dev 用临时）
- access_token TTL: 3600 秒（1 小时）
- refresh_token TTL: 30 天

### 10.2 dev-mock-login 限制

- **仅 dev 环境可用**：`web_config.WECHAT_DEV_ALLOW_MOCK = (IELTS_BUDDY_ENV != 'prod')`
- 生产环境返回 403

### 10.3 跨域

- CORS 配置：`IELTS_BUDDY_CORS_ORIGINS` 环境变量
- 默认仅允许 `127.0.0.1:8000` 和 `localhost:8000`
- 小程序不受 CORS 限制（不走浏览器）

### 10.4 文件上传

- 音频文件大小限制：30MB
- 文件类型校验：`audio/webm / opus / wav / mp3 / mpeg / mp4`
- 文件隔离：按 user_id 分子目录
