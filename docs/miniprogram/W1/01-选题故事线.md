## 一、一句话定位（评审标题 + 海报主标语）

> **雅思搭子 · 你的 AI 雅思考研搭子**：把"开口练口语、动手批作文、随手背单词"变成微信里一句话的事 ——AI 不是噱头，是和学员一起练、一起改、一起复习的搭子。

副标语候选（评审展示 / B 站引流二选一）：

- 候选 A：「在微信里，把雅思考了。」
- 候选 B：「AI 考官、艾宾浩斯复习、雅思词库——打开小程序就能开练。」
- 候选 C：「说出来 → 写下来 → 记住它。三步闭环，全程 AI 陪练。」

## 二、3 个核心卖点（必须全部踩中「AI 是核心 + 微信 AI 生态」两条主线）

### 卖点 1：把口语对练塞进微信对话流

**用户场景**：用户通勤路上想练一个 Part 2 话题，但他不想再装一个 App，也不想点开录音 App。

**产品做法**：
1. 用户在「雅思搭子」小程序内任意页面长按聊天框，说：「来一道 Part 2 关于旅行的话题」。
2. 小程序 **AI 开发模式** 调起自定义 SKILL「口语搭子」的原子接口 `speak.pickTopic(part=2)`，返回话题卡片。
3. 用户点卡片上的麦克风，前端 `RecorderManager` 录音 60–120 秒，回传音频。
4. 服务端用 **Whisper（Core ML 加速，继承自 Web 端 `whisper_service.py`）** 转写。
5. 再调 **小程序 AI 开发模式** 的 SKILL「口语评分」原子接口 `speak.grade(transcript)`，按 4 维（流利度 / 词汇 / 语法 / 发音）出分。
6. 评分 + 转写 + 错词回流入库，自动归入「错词本」和艾宾浩斯复习队列。

**评审抓手**：这条路径打通了「SKILL 调用 + Whisper + AI 评分」三件套，AI 不是装饰，是链路上的关键节点。

### 卖点 2：写作 LLM 批改 + 改写对比，看得见自己的进步

**用户场景**：用户写完一篇 Task 2 议论文，想立刻知道自己的问题在哪。

**产品做法**：
1. 用户进入「写作批改」页，粘贴 Task 1 / Task 2 文本（上限 8000 字符）。
2. 提交后服务端调用 `llm_service.py`（继承自 Web 端）+ **小程序 AI SKILL**「写作批改」，按雅思官方四维（TR / CC / LR / GRA）出分 + 给出改写版本。
3. 前端用 **微信小程序 `rich-text` + diff 组件** 展示原文 vs 改写版本的红绿对比。
4. 批改历史存 `grade_history`（用户隔离），支持「错词一键加入错词本」。

**评审抓手**：把「贴一段文字 → 等 5 秒 → 看到 4 维分数 + 改写对比」做成单页面闭环，避免进入"AI 装饰品"陷阱。

### 卖点 3：艾宾浩斯 + 错词本 + 微信订阅消息，把复习变成习惯

**用户场景**：用户当天该复习哪些词、错过的词怎么办、怎么不错过复习。

**产品做法**：
1. 进入「今日复习」页，自动加载到期词（艾宾浩斯 0/1/2/4/7/15/30 天间隔，沿用 `review_service.py`）。
2. 「错词本」页面按错次降序列出所有答错过的词，支持「批量加入艾宾浩斯复习」「按 Band 筛选」「按时间窗筛选」。
3. 用户首次登录时授权 **微信订阅消息**，每天 21:00 推送一条「今日复习待办」卡片。
4. 用户答对 → 升一级；答错 → 自动回退 + 加入当日复习池。

**评审抓手**：把「科学的记忆曲线」做成可被微信通知拉活的留存工具，是评审「实用性 + 体验感」双维度的硬通货。

## 四、与既有 IELTS Buddy 资产的关系（评审问「这不是新做的吗」时的应答）

| 维度 | 既有资产（CLI / Web） | 小程序新增 | 复用比例 |
|------|------------------------|------------|----------|
| 词库 | 4485 词（Band 5–9）+ 526 精选词 | 直接复用 JSON 资源 | 100% |
| 艾宾浩斯算法 | `review_service.py`（0/1/2/4/7/15/30 天） | 直接复用 Python 服务（部署到云函数或自建 API） | 100% |
| LLM 批改 | `llm_service.py` | 复用 prompt 模板 + API 调用 | 100% |
| Whisper 转写 | `whisper_service.py`（Core ML 加速） | 复用同款模型 + 走云函数 / GPU 服务 | 100% |
| TTS 合成 | `listening_tts_service.py` | 复用 | 100% |
| UI 交互 | 28 个 Web HTML 模板 | 重新设计为 12–15 个小程序页面 | 0%（全部重做） |
| AI 调度 | 手动 LLM API 调用 | 新增 **SKILL 封装 + MCP 接入** | 新增 |

**对评审的一句话答辩**：项目不是从零开始，团队已用 1.5 年沉淀了完整的雅思备考数据闭环（CLI v3.8 + Web v3.8），小程序承担的是「把闭环搬到微信里 + 让 AI 真正进入闭环」的角色。

## 六、关键决策记录（评审答辩时要能讲清楚的故事）

1. **为什么不做综合英语学习，而只做雅思？** → 雅思有官方评分量表（四维 + Band 系数），AI 批改的"准"有客观依据；通用英语学习会被打成"AI 装饰品"。
2. **为什么不直接做 Web？** → 大赛主题是「与 AI 共生」+ 微信小程序是评审载体；且微信生态独有的 AI 开发模式 + 订阅消息 + ClawBot 是评审「创新性」维度的胜负手。
3. **AI 是怎么进入产品核心的？** → 三个核心路径都离不开 AI：口语转写评分、写作批改改写、复习推荐智能调度；任何一条被砍掉产品都会塌。
4. **为什么用「搭子」而不是「老师」？** → 评审反感"教育 + AI 替老师"的双减叙事；"搭子"强调陪伴与练习，对应微信"轻交互"调性，也规避办学许可类目风险。
