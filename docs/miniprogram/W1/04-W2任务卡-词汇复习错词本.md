## 一、W2 目标

把「学 → 复习 → 错词回收」的学习闭环在小程序里跑通，让评审在 9/7 当天扫码即可看到完整流程。

## 二、三个核心页面 + 1 个登录页（共 4 页）

### 2.1 页面 A · `pages/auth/login`（登录页）

**目标**：让用户最快进入学习闭环。

| 项 | 内容 |
|----|------|
| 入口 | 小程序冷启动 + Tab 4「我」未登录态 |
| 主交互 | 微信一键登录（`wx.login` → 后端换 JWT） |
| 备选交互 | 手机号 + 验证码登录（防微信风控） |
| 字段 | openid / session_key / 用户名（默认 wx_<openid 前 8 位>） |
| 边界 | 静默登录失败 → 弹窗提示，不阻塞 |
| 验收 | 微信登录后 1 秒内跳转 Tab 1 首页；session 持久化到 storage |
| 后端复用 | `web/auth/router.py` 的 `/api/auth/login` |
| 工作量 | 0.5 人天 |

### 2.2 页面 B · `pages/study/index`（学习首页）

**目标**：把"词库浏览 + 抽词 + 测验"三个 Web 页合并为一个小程序页面内的 Tab。

| 项 | 内容 |
|----|------|
| 入口 | Tab 1 |
| 布局 | 顶部：今日计划卡（剩余天数 / 待复习数 / 计划完成率）+ 顶部 Tab 切换（**浏览 / 抽词 / 测验**）|
| 子页面 1 - 浏览 | 左侧 Band 5–9 选择器、右侧 Topic 筛选、双列卡片瀑布流 |
| 子页面 2 - 抽词 | 选 Band + 数量 → `swiper` 组件一卡一词 → 翻页即下一词；底部"加入复习"按钮 |
| 子页面 3 - 测验 | 选 Band + 模式（en2zh / zh2en）→ 单题作答 → 即时判分 → 完成出报告 |
| 数据源 | `vocab_service.py` + `learning_records` 表 |
| 后端 API | `GET /api/vocab/list?band=&topic=&page=` / `POST /api/vocab/quiz/submit` |
| 验收 | 三个子 Tab 切换流畅；测验答错自动加入错词本 |
| 工作量 | 2.0 人天 |

### 2.3 页面 C · `pages/review/index`（复习首页 + 错词本合并）

**目标**：今日到期复习 + 错词本 + 收藏，三合一。

| 项 | 内容 |
|----|------|
| 入口 | Tab 2 |
| 布局 | 顶部统计行（今日到期 / 本周到期 / 错词数 / 收藏数）+ 三个 Tab 切换（**今日复习 / 错词本 / 收藏**）|
| 子页面 1 - 今日复习 | 加载所有到期词（艾宾浩斯 0/1/2/4/7/15/30 天），按 Band 排序，一卡一词 |
| 子页面 2 - 错词本 | 按错次降序 + 按 Band 筛选 + 批量加入复习 |
| 子页面 3 - 收藏 | 用户手动收藏的单词，可批量复习 |
| 答题交互 | 单卡片：单词 → 翻转显示释义 + 例句 → "认得 / 不认得"按钮 |
| 数据源 | `review_service.py` + `personal_vocab` 表（错词 + 收藏） |
| 后端 API | `GET /api/review/due` / `GET /api/review/mistakes` / `POST /api/review/submit` |
| 验收 | 艾宾浩斯算法准确（与 CLI 行为一致）；答错立即回流；错词按错次正确排序 |
| 工作量 | 2.5 人天 |

### 2.4 页面 D · `pages/me/index`（我 - 最小可用版）

**目标**：让 W2 Demo 不止 3 个 Tab，凑齐 4 Tab；同时承接 W3+ 工具入口。

| 项 | 内容 |
|----|------|
| 入口 | Tab 4 |
| 布局 | 头像 + 昵称 + 微信绑定状态 + Streak 天数 + 累计学习词数 + 入口列表（数据复盘 / 写作批改 / 工具集 / 设置） |
| W2 范围 | 仅做骨架 + Streak + 累计词数；其他入口点击提示"敬请期待" |
| 数据源 | `stats_service.py` + `users` 表 |
| 后端 API | `GET /api/stats/summary` |
| 验收 | 显示当前用户基础统计；其他入口有占位 |
| 工作量 | 0.5 人天 |

## 三、4 个后端接口（W2 必须暴露）

| 接口 | 用途 | 复用 Web 路由 |
|------|------|---------------|
| `POST /api/auth/wx-login` | 微信登录 | 新增（Web 端没有，但沿用 `security.py` JWT 签发） |
| `GET /api/vocab/list` | 词库列表 | 沿用 `/api/vocab/list` |
| `GET /api/review/due` | 今日到期复习 | 沿用 `/api/review/due` |
| `POST /api/review/submit` | 复习结果提交 | 沿用 `/api/review/submit` |
| `GET /api/review/mistakes` | 错词列表 | 沿用 `/api/personal/mistakes` |
| `GET /api/stats/summary` | 统计摘要 | 沿用 `/api/stats/summary` |

> W2 后端总体工作量：约 1.0 人天（沿用既有 Python 服务，仅暴露新端点 + wx-login）。
