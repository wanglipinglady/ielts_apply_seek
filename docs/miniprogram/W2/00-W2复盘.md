## 二、本周遇到的问题 + 解决方案（**实诚记录**）

### 问题 1：写代码前没 grep 源码，凭直觉写错 API（出现 5 次）

| # | 我凭直觉写的 | 实际 API（grep 后修正） |
|---|--------------|------------------------|
| 1 | `container.learning.record_attempt(word=...)` | `ReviewService.record_learn(word, correct, source)` |
| 2 | `container.learning.get_mistakes(user_id, limit)` | `MistakeService.list_wrong_words(min_wrong=1, limit)` |
| 3 | `get_vocab_service(request)` | `get_vocab_service()` （**无参**）|
| 4 | `ReviewService(container=..., user_id=...)` | 必须用 `Depends(get_review_service)` 注入，user_id 内部绑定 |
| 5 | `vocab.get_by_text(word)` | `vocab.get_word(word)` |

**根因**：之前承诺"代码前先 grep 源码"未严格执行。

**纠正措施**：每个 W2 后端端点都 grep 真实方法签名 → 失败 5 次 → 修正 5 次 → 全过。

**长期方案**：把这个教训写入 `CLAUDE.md`（已加） + 所有写代码任务默认前 5 分钟是"grep 阶段"。

### 问题 2：写前端 app.wxss 时用 .ts 扩展名

**根因**：微信小程序的 `.wxss` 不能用 `.ts` 命名，我误用。

**纠正**：手动 `mv` 修正（`app.json.ts` → `app.wxss`）。

### 问题 3：批量 Write 工具调用被系统跳过（用户报告）

**根因**：用户报告"拒绝执行的写动作好像也没有在批处理中完成自动写入，缺少文件"。

**根因分析**：TRAE 客户端工具调用有去重 / 跳过机制，**短时间内**对同一路径发多次 Write 会被视为"已执行"。

**纠正**：每个文件**只 Write 一次**，绝不重复；遇到"跳过"立即**停下来**报告，不重试。

### 问题 4：用户原"手动审批"模式反复弹窗

**根因**：TRAE 客户端 → 设置 → Agent 操作审批 默认手动模式。

**用户已修复**：切换为"自动审批"，后续不再弹窗。
