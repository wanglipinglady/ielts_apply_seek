# 知识卡片制作规范

## 概述

本文档定义了知识卡片的文件格式、结构规范，以及如何将 Word 文档转换为系统可用的 JSON 格式。

## 目录结构

```
courses/
├── 主题名称/
│   ├── meta.json          # 元数据
│   ├── content.json       # 结构化内容（系统集成用）
│   ├── content.md         # Markdown 版（CLI 阅读用）
│   └── *.docx            # 原始文件（用户下载）
```

## meta.json 规范

```json
{
  "id": "course_主题名称",
  "topic": "主题名称",
  "title": "Sentence XX · 主题名称",
  "source": "剑桥雅思X",
  "source_file": "原始文件名.docx",
  "tags": ["标签1", "标签2"],
  "version": "1.0",
  "author": "IELTS Buddy",
  "created_at": "YYYY-MM-DD",
  "updated_at": "YYYY-MM-DD"
}
```

## content.json 规范

```json
{
  "topic": "主题名称",
  "source": "来源",
  "core_sentence": {
    "en": "英文例句",

  },
  "vocabulary": [
    {
      "word": "单词",

      "meaning": "释义",

  },

  }
}
```

## Word 文档格式要求

### 文件命名

```
Sentence{编号}_{主题名称}_知识卡片.docx
```

示例：
- `Sentence01_太空探索_知识卡片.docx`
- `Sentence02_教育改革_知识卡片.docx`

### 标题格式

| 内容 | 标题格式 |
|------|----------|
| 核心例句 | 卡片 X · 核心例句 |
| 语法笔记 | 卡片 X · 语法笔记 |
| 核心词表 | 卡片 X · 核心词表（X个关键词） |
| 主题归纳 | 卡片 X · 主题归纳 |
| 反驳词汇 | 卡片 X · 反驳/辩驳类词汇 |
| 太空主题词汇 | 卡片 X · 主题归纳 — 探索太空主题词汇 |
| 探索动词 | 卡片 X · 探索类动词 |
| 综合应用 | 卡片 X · 综合应用 — 雅思写作模板 |
| 学习总结 | 卡片 X · 本课学习总结 |

### 词汇表格式

使用表格，包含列：
- 单词
- 音标/释义（合并列）
- 记忆方法（可选）
- 同义词（可选）

## 转换流程

### 步骤 1：准备 Word 文档

1. 创建符合上述格式的 Word 文档
2. 保存为 `.docx` 格式
3. 放入 `courses/{主题名称}/` 目录
4. 重命名为标准格式

### 步骤 2：运行转换脚本

```bash
# 安装依赖
pip install python-docx

# 转换单个文件
python scripts/convert_course.py courses/太空探索/Sentence01_太空探索_知识卡片.docx

# 批量转换所有 docx 文件
python scripts/convert_course.py --all
```

### 步骤 3：检查输出

检查生成的三个文件：
- `content.json` - 系统使用
- `content.md` - 阅读使用
- `meta.json` - 元数据（可能需要手动补充）

### 步骤 4：手动补充

如果自动提取不完整，手动编辑：
- `meta.json` 中的 `created_at`、`author`
- `content.json` 中的 `summary`
- 词汇表的详细释义

## 验证清单

- [ ] 文件命名符合规范
- [ ] `meta.json` 所有必填字段完整
- [ ] `content.json` 包含核心例句、词汇、模板
- [ ] `content.md` 格式正确，可正常阅读
- [ ] 词汇数据准确（单词、音标、释义）

## 更新现有卡片

1. 更新 `courses/{主题}/` 下的 `docx` 文件
2. 重新运行转换脚本
3. 检查并更新 `content.json` 和 `meta.json`

## 注意事项

- 不要手动修改 `content.json` 的结构，只修改内容
- 保留原始 `docx` 文件用于下载
- 定期备份 `courses/` 目录
- 多人协作时，通过 Git 管理版本
